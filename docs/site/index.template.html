Plugins for Telegram iOS,
in the shape of exteraGram.

A plugin runtime built into a sideloaded IPA. It reads the same plugin files, exposes the same names, and runs them on JavaScriptCore instead of Python — so the plugins people already wrote for Android mostly work without being rewritten.

Read the API Repository

Same file, same names

__id__, BasePlugin, add_hook, create_settings, HookResult: a plugin ported from the SDK keeps its metadata block, its hook registrations and its settings tree.

Installed from a chat

A .plugin file opened in the client offers to install itself. Nothing is baked into the binary, so the IPA can be re-signed without losing plugins: they live in the app's own documents directory.

Real surfaces, not stubs

HTTP verbs, proxies, swizzled Objective-C methods, runtime class construction, URL intents, settings sub-pages, deleted-message retention: these run against the app's own objects. Android-only parts log instead of pretending.

What runs

Each plugin is evaluated in its own JSContext, in this order: the bootstrap, then the plugin body, then a finalise step. Nothing is shared between plugins except the host bridges, and every value that crosses into Swift is a JSON string.

One queue serialises all script work. A plugin that blocks it blocks the others, which is why network and file work belongs in run_on_queue.

Install

  1. Build or download Telegram-13.1.1-sideload.ipa.
  2. Install it with Sideloadly and a free Apple ID. The bundle id is unique to this build, so it installs beside the App Store client.
  3. Open a .plugin file in any chat and accept the install prompt, or use Settings → Plugins → Install.
  4. Enable the plugin with the switch in the plugin list. Disabling it unloads the script and restores every hook it installed.

What a plugin looks like

js
var __id__ = "hello_world";
var __name__ = "Hello World";
var __version__ = "1.0.0";

class HelloWorldPlugin extends BasePlugin {
    on_plugin_load() {
        this.add_hook("messages.setTyping");
        this.log("loaded");
    }

    pre_request_hook(name, account, request) {
        this.log(name);
        return new HookResult();
    }
}

var Plugin = HelloWorldPlugin;

Where it differs

JavaScriptCore is not Python, and iOS is not Android. Two kinds of difference are worth knowing before porting:

  • Python syntax. A file whose body is Python is refused with a message saying so, rather than half-loaded. The metadata block, the plugin class and the settings tree carry over; the language does not.
  • Android-only surfaces. Field access by name, MVEL conditions, bundled wheels and Java-proxy generators have no counterpart. They are present, they log the reason, and a plugin's own guard takes the safe branch instead of the handler never firing.

The full list, with what is real and what only logs, is section 19 of the reference.
